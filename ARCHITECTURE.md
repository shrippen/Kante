# Architecture

How this repository is meant to be built. Where the code differs today is listed under
"Known deviations". Change this file in the PR that changes the structure.

## What it does

Kante is the design system of all shrippen projects: one palette, and from it a
stylesheet for web pages, a QML module for apps, a theme and a UI kit for Kimai plug-ins,
and a style for KDE. The projects build nothing of their own; they link the built
stylesheet or copy the module.

## Building blocks

| Path | Its one task |
|---|---|
| `tokens/palette.json` | The one source of every colour, font, line and level, for all themes (dark, Leinen, Kante Light, Gold). |
| `tokens/variables.src.css`, `tokens/variables.css` | The palette as CSS custom properties, and the roles built on them (text, ground, accent, state). The `.src.css` is written by hand with `{{theme.name}}` placeholders for colours; `tools/build-variables.py` fills them from the palette into `variables.css`. |
| `css/`, `js/`, `fonts/` | Kante for the web: the components' styles, their behaviour, the map and wall display scripts, the offline fonts. |
| `qml/Kante/` | Kante for apps: `KanteStyle` (all roles, the one place that picks the theme), one file per component, the skins for Qt's own controls. `KantePalette.qml` is generated. |
| `qml/Kante/KanteNoteState.qml`, `KanteStaffFrame.qml` | What the note views share, without a look: the state of each note (played right, wrong, technique), kept for the two staffs and the two lanes; and the staffs' room, line layouts and loop split. |
| `qml/KantePlasma/` | The few components for Plasma widgets, which keep Plasma's theme. |
| `qml/tests/`, `qml/demo/Gallery.qml` | A test and a gallery entry for every component. |
| `kimai/knust/` | Knust: the Kimai plug-in that gives Kimai Kante's look. Released on its own (`knust-v*`). |
| `kimai/kit/` | The UI kit (`kpu-*`) that every shrippen Kimai plug-in copies in. |
| `union/` | Kante as a style for KDE's Union engine and as KDE colour schemes (a spike). Only `template/` is written by hand. |
| `templates/` | The starting point for a landing page. |
| `tools/build-*.py`, `build.sh` | The build: generates everything below from the sources above. `tools/knust-zip.sh` packs Knust's release. |
| `tools/check-*`, `tools/qmllint.sh`, `tools/structure-check.py` | The checks the build and CI run: tokens, release lists, QML tests, Union, structure limits (a synced copy). `check-kit.sh`, run by hand, lists the plug-ins beside this repository that lack the current kit. |
| `tools/specimen.html`, `tools/shoot-specimen.py` | One page with every web component, and its pictures in each theme. |
| `docs/v1/` | The built web files. `shrippen.github.io` copies them and serves them to every page. Generated. |
| `docs/` (rest), `proposals/`, `README.md` | Kante's and Knust's own pages; design proposals by date, kept as record; the catalogue of every token and component. |
| `.design-sync/` | The bundle for Claude Design, built from the same sources. |
| `tools/release-notes.sh`, `tools/sync-release-notes.sh` | The release-notes tool of all projects and its distribution. |

## Layers

```
                     tokens/palette.json   (the one source)
                               │ generated by build.sh
      ┌──────────────┬─────────┴─────┬──────────────────┐
      ▼              ▼               ▼                  ▼
 variables.css   KantePalette   knust-palette      union/ styles
      │              │               │              and colours
      ▼              ▼               ▼                  │
 css/ + js/      KanteStyle      knust.css ─► kit.css   │
      │              │               │           │      │
      ▼              ▼               │           │      │
 docs/v1/        components, skins   │           │      │
      │              │    │          │           │      │
      │              │    ▼          │           │      │
      │              │  KantePlasma  │           │      │
      ▼              ▼    ▼          ▼           ▼      ▼
 web pages      apps and Plasma     Kimai with its    KDE desktop
 (link /v1/)    widgets (copy       plug-ins (Knust
                qml/Kante; widgets  installed, kit copied in)
                also KantePlasma)
```

- A value stands once, in `tokens/palette.json`. Everything else that holds a colour is
  generated from it and never edited by hand.
- No raw colour or font outside `tokens/`. CSS uses the custom properties; a QML
  component asks `KanteStyle`, never `KantePalette`, and never decides the theme itself.
- Generated files are committed and changed only by `./build.sh`: `docs/v1/`,
  `qml/Kante/KantePalette.qml`, `qmldir` and `fonts/`, `tokens/palette.qml`,
  `tokens/variables.css`, `qml/KantePlasma/KantePlasmaButton.qml`, `knust-palette.css`, the kit's
  `assets.html.twig`, `union/styles/`, `union/colors/`.
- A shape or behaviour several components share is written once and used by them: in
  CSS as one rule or property, in QML as one component or function.
- Web and apps show the same thing under the same name; a theme has one name everywhere.
- Knust takes its colours from the generated palette only. The kit uses Knust's and
  Kimai's properties with a fallback, so it also works without Knust.
- Kante depends on no project: it builds and passes its checks without any of them.
  A missing element is added here first, also when only one project needs it; no
  project solves it locally (the GUI rule in `AGENT-RULE.md`).
- Every QML component has a test and a gallery entry, filed under the component's name.
- `tools/` builds, checks, packs and distributes Kante. A tool that has nothing to do
  with Kante does not live here.

## Where new things go

| Change | Touch |
|---|---|
| A new or changed colour | `tokens/palette.json`, `./build.sh`, README |
| A new or changed font or level | `tokens/palette.json` and `tokens/variables.src.css` (checked against each other), `./build.sh`, README |
| A new role (what a colour is for) | `tokens/variables.src.css` and `qml/Kante/KanteStyle.qml`, under the same name; README |
| A new web component | `css/components.css`, behaviour in `js/`, README, `tools/specimen.html`, its catalogue page in `proposals/` |
| A change to how note states work, or to how the staffs lay out lines and take their size | `KanteNoteState.qml` or `KanteStaffFrame.qml`, never one view alone; the views `KanteBassStaff`, `KanteTabStaff`, `KanteTabLane`, `KanteKeyLane` only hand on |
| A new QML component | A file in `qml/Kante/`, a test in `qml/tests/`, an entry in `qml/demo/Gallery.qml`, README; `./build.sh` writes `qmldir` |
| Motion | The `prefers-reduced-motion` block at the end of `css/components.css`; `KanteStyle.motion` in QML |
| Something for Kimai's look | `kimai/knust/`; something Kimai plug-ins share: `kimai/kit/`, then `kimai/kit/bin/sync.sh` per plug-in |
| A theme or variant | `tokens/palette.json`, its block in `tokens/variables.src.css`, `KanteStyle`, the build scripts that list themes |
| A proposal before it is built | `proposals/<year>-<month>-<name>/` |

## Known deviations

- The Union build calls Leinen "Kante Light", which is another theme
  (`AUDIT.md`, finding 4).
- The bass and tablature staffs are still over 800 lines each, and `normalizeBars` and
  the note spelling in the bass staff are over the limits; the layout itself is already
  split into lines, beams, rests, chords and the rest (`AUDIT.md`, finding 9).
- What is left of `AUDIT.md`, finding 1: `KanteTabLane` and `KanteKeyLane` keep their
  own `barLabel` and note search (the same text as in `KanteStaffFrame`, which they do not
  hold); `KanteBassStaff` and `KanteTabStaff` each have their own `computeLayout`,
  `normalizeBars`, `layoutBeams`, `layoutSections` and `xOf`, which differ in the notation
  (staff lines against strings, `sys` in the sections, other paddings).
- Three charts each compute their own axis steps (`AUDIT.md`, finding 2).
- The cut corner is written out about 25 times in the stylesheet
  (`AUDIT.md`, finding 7).
- `js/shrippen.js` does everything in one function (`AUDIT.md`, finding 5).
- Tests and gallery are filed by version number, not by component
  (`AUDIT.md`, finding 6).
- `css/components.css` writes the dark palette out again for the areas that stay
  dark in every theme, and holds a few raw `rgba()` colours; the token check allows
  the first (not in `AUDIT.md`).
- Not every component has a gallery entry (skins, helpers such as `KantePolygon`,
  the Plasma components and others); `KantePageTitle` has no test either
  (not in `AUDIT.md`).
- Two components read `KantePalette` directly (`KanteSticker`, `KanteRehearsalMark`;
  not in `AUDIT.md`).
- The release-notes tool of all projects lives here (`AUDIT.md`, finding 8).
