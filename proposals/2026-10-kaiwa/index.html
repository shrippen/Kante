Kante for Kaiwa

Kaiwa is a Japanese conversation trainer (Rust, Qt 6 / Kirigami, Plasma widget). This page lists what its GUI needs, what Kante already has and the seven elements that are missing. Each comes with a sketch in Kante's roles, a proposed CSS and QML API and a decision. Nothing here is in the stylesheet yet. Requirements in brackets are from Kaiwa/spec/LASTENHEFT.md.

1 · Ruby text (furigana)

駅えきまでは歩あるいて五分ごふんです。

駅えきまでは歩あるいて五分ごふんです。

駅えきまでは歩あるいて五分ごふんです。

Readings over kanji in three densities: all, only new words (cyan, the "marked" colour), none. The space for the readings stays reserved, so switching does not move the lines. [/LF110/, /LF211/, /LL202/]
CSS .ruby[data-ruby="all|unknown|none"], ruby.is-new. QML KanteRubyText { segments: [{text, reading, isNew}]; density: KanteRubyText.All }: Qt Text has no ruby, so a Flow of base/reading pairs that wraps at segment borders, scales with the font.

D-1 Should new words take cyan readings (marked), or stay muted like the rest? Proposal: cyan.

Under a character's turn: replay, slow, translate as quiet buttons (one primary per view stays the talk button). Under the learner's turn: what the recogniser heard, and an "unsure" state in warn with a "misheard" link that keeps the turn out of the learner model. [/LF111/, /LF113/]
QML KanteMessage gets nothing new: tools and the heard line are children under the text. Proposed: KanteHeardLine { text; unsure } as a small part, so both projects and tests draw it the same way.

D-2 Separate KanteHeardLine, or plain children in Kaiwa? Proposal: separate (it has a state and an action).

3 · Talk button

The one big control of a conversation. Five states, each with its own text and mark shape, never colour alone: ready (square), listening (primary fill and a live level as segment display, A10), thinking (diamond and running light, A21), speaking (aqua square, tap interrupts), error (triangle, red bottom bar, the action in the second line). Height --h-l + 16 px for shaky hands; both cuts like a primary button. [/LF100/, /LF103/, /LF505/, /LL202/]
CSS .talk[data-state]. QML KanteTalkButton { state: KanteTalkButton.Listening; level: 0..1; hint: "hold space"; mode: Hold | Toggle } and KantePlasmaTalkButton for the widget.

D-3 Is a 64 px control within the height scale acceptable (rule: 32/40/48), or should it stay at --h-l 48 px? Proposal: a new step --h-xl 64 px, only for this control.

The hint card as it is, with the diff as its title: removed text struck through in red ink, inserted text with the cyan tint and underline (marked), never colour alone (strike and underline carry it). The row form is the plasmoid's one-line feedback. [/LF301/, /LF302/, /LF307/, /LF503/]
CSS .diff del, .diff ins. QML KanteDiffText { parts: [{text, kind: Same | Removed | Added}] }, placed in the existing hint card (QML has no hint card yet: KanteHintCard joins as the QML twin of .hint-card).

D-4 Mapping of the four severities: blocks understanding = red, wrong = yellow (warn), unnatural = blue, style = no tier. Proposal as shown.

5 · Pitch curve

target 箸 (は↘し)youaccent kernel

Morae on the x axis, two levels H/L as the target (dashed, muted), the learner's F0 normalised to their own range (cyan line, data). The kernel is a square in the primary colour, a missed kernel a red square, as Kante markers are square. Also used for shadowing: the model's curve and the learner's on top of each other. [/LF321/, /LF330/]
CSS svg.pitch with .target, .actual, .kernel, .miss. QML KantePitchCurve { morae: ["は","し"]; target: [1,0]; kernel: 1; actual: [..]; missAt: -1 }, built on the drawing of KanteLineChart.

D-5 Should the learner's line take cyan (data) or the series colour 0 of the charts? Proposal: cyan, the target is not a series.

7 · Daily goal in the panel

12 d

The compact form of the widget shows the day's goal and the streak. Left: a ring around the streak count (round, like an icon, since it sits in the icon slot). Right: a vertical segment display (A10), square like the rest of Kante. With System style both use Kirigami.Theme.highlightColor. [/LF500/, /LF601/, /LF602/]

D-7 Ring or segments? Proposal: segments; they read at 22 px and follow the square marker rule.

Order

Kaiwa M1 needs 1–4, M3 needs 5, M4 needs 7 and KantePlasmaTalkButton, M5 needs 6. Each element lands as CSS in components.css (motion in the reduced-motion block), the QML component with a test in qml/tests and an entry in qml/demo/Gallery.qml, and a README row, as the working rules ask.
